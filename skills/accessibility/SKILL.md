# Accessibility

Use this skill when a request changes an interactive surface or claims accessibility support.

## Workflow

1. Navigate the surface with the keyboard only and record focus order.
2. Confirm every control has an accessible name, role and state.
3. Run the axe audit in the browser lab and record the raw result.
4. Check error messages are announced and recovery is possible.
5. Check contrast and reduced-motion behavior.
6. Convert each defect into a reproducible check.

## Constraints

- An axe pass alone is not proof of accessibility.
- Do not claim a screen-reader result that was not actually observed.
- Record violations with their impact and affected nodes.
