# Documentation

Use this skill when a change alters commands, configuration, evidence or user-visible behavior.

## Workflow

1. Read the implementation and run the documented command before writing.
2. State what the reader can do, not what the team intended.
3. Include exact commands, required configuration and expected output shape.
4. Mark unverified or environment-dependent behavior explicitly.
5. Update every document that repeats the changed fact.
6. Remove claims that no longer have evidence.

## Constraints

- Do not invent benchmarks, screenshots or verdicts.
- Do not imply OpenPitStop verified something it did not verify.
- Keep secrets and private tokens out of examples.
