# UNSLOP

Use this skill when writing or editing prose the user will read: commit
messages, documentation, README sections, replies and release notes.

Adapted for PitCrew from the public UNSLOP SKILL.md (unslop.live); the local
editorial guidance needs no connection and no paid API.

## The rule

Improve the prose without losing meaning, facts, qualifications or the
author's voice. The user's facts and intent are preserved exactly; the AI
shape around them goes.

## Slop patterns to remove

1. Filler openers and closers ("Great question!", "Hope this helps!",
   "In today's fast-paced world").
2. Hedge stacking ("it's worth noting that", "it should be mentioned that").
3. Rule-of-three padding invented to sound balanced.
4. Em-dash and colon cadence used as decoration.
5. Vague intensifiers ("significantly", "seamlessly", "robust") that carry
   no information.
6. Bullet lists where one plain sentence is shorter.
7. Puffed verbs ("leveraging", "utilizing" → "using").

## Constraints

- Never change a fact, number, claim, qualification or named entity while
  de-slopping. If a sentence is ambiguous, keep the ambiguity.
- Do not invent missing information to make prose smoother; mark the gap
  instead.
- In documentation, keep technical terms the reader needs, even when they
  are unglamorous.
- Commit messages follow the repository's existing subject/body style.
